# Phase 2 real-metadata benchmark protocol

Protocol `phase2-real-metadata-20260913-v1` is declared before the expanded-data benchmark. It adds bounded engineering measurements and source-determined metadata checks; it changes no alpha acceptance threshold, holdout, scientific endpoint, or ranking weight.

## Inputs and immutable scope

Use the acquisition worker's completed `data/final_campaign_20260913/expanded/corpus/literature.jsonl`, `datasets.jsonl`, and `ACQUISITION_RECEIPT.json`, plus separately manifested real metadata supplements if needed. Bind exact input bytes and the acquisition receipt by SHA-256 before measurement. Preserve original records and source provenance. Refuse missing/conflicting stable identities. Identical repeated identities are counted once, with duplicate counts reported. Counts are catalog accessions/publication IDs, not independent studies, participants, donors, or experiments. Cross-source biological dependence remains unknown unless documented.

The benchmark generates no records for the real corpus. Synthetic fixtures are used only by tests and are never counted as real acquisition. Use a fresh versioned derivative output directory. Do not overwrite completed benchmark results, inspect/rescore the sealed holdout, download models/raw datasets, or make network requests.

## Workloads and engineering bounds

Order unique records by SHA-256 of their stable identity, with identity as the tie breaker. Measure nested literature subsets of 100, 500, and all available records; dataset subsets of 32, 100, and all available records. Deduplicate equal size points and report actual sizes, not requested floors. Cap accepted workload at 10,000 literature and 5,000 dataset records to prevent accidental bulk execution. This cap is a computational boundary, not a scientific coverage threshold.

Measure JSON input loading, application Catalog ingestion with FTS construction, isolated FTS optimize time, query latency p50/p95, deterministic matching including dataset normalization, context-only evidence compilation, sampled peak process-tree RSS, disk bytes, and exact catalog-payload cache hits. FTS insertion is integrated into `Catalog.upsert`; report that combined stage honestly rather than claiming a separate pure parser benchmark. Use at least 20 timed warmed FTS query repetitions per nonempty query family; the first untimed query establishes expected replay IDs. Count actual query/candidate assessments and normalize their measured throughput to 1,000 assessments; that normalization does not create 1,000 distinct datasets.

Predeclared local usability bounds are FTS query p95 <= 5 seconds, matching <= 30 seconds per 1,000 actual candidate assessments, and sampled process-tree RSS <= 8 GiB. These deliberately broad limits permit interactive local use without exhausting the observed 96-GB workstation. They are engineering limits only, not biological power, population accuracy, or modified frozen acceptance criteria. CPU execution uses the existing deterministic implementation; the optional qualified MiniLM encoder uses CPU and its existing four-thread/batch-16/token-256 configuration. No GPU inference is performed here. Report RSS sampling interval and its inability to capture every instantaneous allocation peak.

## Source-determined metadata evaluation

Construct questions from catalog source fields before looking at ranking output: one question for each observed qualified modality family and recognized organism, then joint organism/modality questions, in stable lexical order, capped at 24. Record the first stable-ID source anchor for every question. Questions ask which catalog entries explicitly satisfy those narrow metadata requirements; they are not claims of unanswered biology or downstream statistical answerability. Do not include accession IDs in query text.

The independent reference annotator reads raw `organisms` and `assay_types` fields with source URL/locator provenance. It does not call the product matcher or its ontology to assign labels. It uses a frozen literal reference table for conventional human/mouse/rat/zebrafish/fly/Arabidopsis/E. coli/chicken species and the established clinical-registry, bulk/single-cell transcriptomic, genomic, microbiome, proteomic and metabolomic assay families. Exact recognized matches are `OBSERVED_FIT`; fully recognized incompatible fields are `OBSERVED_MISMATCH`; absent provenance, absent fields or unrecognized reference values remain `UNKNOWN` with the reason recorded. Unknown is never a negative label. A known essential mismatch can establish mismatch even when another field is unknown. Report observed wrong-modality and wrong-organism counts separately, and do not claim a covered challenge family when its denominator is zero.

Compare unchanged application methods on the identical candidate universe: FTS lexical order; weighted heuristic without the eligibility ordering; compatibility-only (retrieval component removed); compatibility plus lexical relevance; and, when the existing qualified local MiniLM is supplied, pretrained semantic order and compatibility plus semantic relevance. Ablations reuse the existing 0.8/0.2 weights without fitting. Report judged precision@5, recall@10, reciprocal rank, known-label nDCG@5, confirmed-invalid top count and unknown top-k counts with explicit numerators/denominators. Unknowns are excluded only from judged-label denominators and remain visible in full rankings. Report the source-anchor/self-rediscovery limitation and lack of held-out/expert calibration. No method is required to manufacture improvement when baselines tie.

Check zero observed-mismatch candidates promoted to qualified by the compatibility-aware path, no observed source-fit wrongly excluded, exact deterministic ranking replay, and explicit unknown handling. Retain all outputs and any failures; do not change labels, selection, weights or bounds after observing a result. This is metadata-contract evaluation, not external scientific validation.

## Compiler, cache and separate-process recovery

Feed one context-only metadata evidence item per actual acquired literature record into the existing compiler, preserving stable IDs and source locators. These are workload/context records, not model-extracted biological claims; `independent_support_count` remains unknown and no item may answer a biological question. Report compilation workload and result hashes. Reversing input order must preserve the deterministic result.

For recovery, launch a separate child process that commits exactly the first half of the stable dataset partitions and writes a receipt, then calls `os._exit(71)` without closing the catalog. Verify the nonzero child exit and committed partial IDs/hashes. A second child reopens the same catalog, validates existing payload hashes and inserts only missing identities. Verify exact final IDs, unchanged existing payloads, one current record/version per identity, no duplicates, and a result digest equal to a clean catalog. Record both commands, exits, counts and receipts. This is a real process interruption of task-owned SQLite state; no protected artifact is involved.

Cache replay reads the committed catalog payloads without reinserting them, records exact hit/miss counts and digests, and repeats queries/rankings. Network access is disabled in the benchmark process and model loaders use local-only resources. Record any attempted connection as a failure rather than hiding a fallback.

## Completion and reporting

Write source/model/protocol/code fingerprints, hardware/environment, commands, measured values, check results, label provenance, full candidate denominators, limitations and output hashes under the derivative scale folder. Distinguish engineering PASS from metadata-evaluation PASS and stronger scientific validation that was not performed. A missing real challenge family or failed required check prevents claiming that family passed. Commit the benchmark implementation, meaningful tests, this protocol and a concise result report; keep datasets, model weights, SQLite indexes, candidate exports and timing logs outside Git.
